# 药品仓库物资管理系统

根据提供的简要需求实现的基础版。包括 Python 本地版和 GitHub Pages 在线演示版，前端使用 Tabler 组件样式。

## GitHub Pages 在线演示版

`docs/` 是可以直接发布的静态网站。首次打开会自动加载 12 种药品、4 家供应商、3 个仓库及出入库测试流水。通过浏览器内的 SQLite 执行数据库触发器，修改保存在访问者自己的浏览器中；不同同学之间不共享数据。页面提供“恢复测试数据”按钮。

GitHub 仓库上传后，在 **Settings → Pages → Build and deployment** 中选择 **Deploy from a branch**，分支选 `main`、目录选 `/docs` 并保存。等待 GitHub Pages 部署完成后，使用该设置页面显示的站点网址访问；仓库源码页面的网址不是管理系统网址。

在线演示版的样式、图标和 SQLite 运行组件均随项目提供，不依赖外部 CDN。浏览器需要允许网站存储；清除网站数据会清除该浏览器中的修改。

## 启动

需要 Python 3.9 或更新版本。在本目录运行：

```powershell
python app.py
```

浏览器打开 http://127.0.0.1:8000 。按 `Ctrl+C` 停止。首次启动会自动创建 `data/warehouse.db`，无需单独安装数据库。

若 8000 端口已被占用，可在 PowerShell 中执行：

```powershell
$env:WAREHOUSE_PORT = '8001'
python app.py
```

## 使用顺序

当前本地交付数据库已导入一组演示数据。GitHub 源码不包含本机运行数据库；克隆源码后，可先执行 `python seed_demo.py` 创建测试数据，再启动系统。数据规模、场景和再次导入方法见 `测试数据说明.md`；完整库存快照见 `demo_inventory.csv`。

1. 在“药品资料”中创建药品并设置预警线。
2. 在“供应商”和“仓库资料”中建立基础资料。
3. 在“入库管理”登记入库，库存会自动增加。
4. 在“出库管理”登记出库。库存不足时，整笔出库会被拒绝。
5. 在“库存查询”和“库存预警”中查看结存与低库存提醒。补货达到预警线后，提醒会自动解除。

入库单与出库单作为业务流水，创建后不提供修改或删除。已有业务流水关联的基础资料也不能删除，以免破坏历史记录。列表中的业务流水显示最近 300 条，数据库保存全部记录。

## 数据库规则

- `receipt_add_stock`：入库后增加对应药品和仓库的库存。
- `issue_check_stock`、`issue_deduct_stock`：出库前校验库存，出库后扣减。
- `stock_low_insert`、`stock_low_update`：库存低于药品预警线时创建待处理提醒。
- `stock_recovered`：库存恢复到预警线后自动解除提醒。
- `drug_min_changed_low`：修改预警线后同步提醒状态。

该版本适合单机演示和基础管理。尚未包含用户登录、权限、批次与效期、扫码、报表导出、多人部署和备份调度。正式业务使用前，应补齐这些能力并建立数据库备份制度。

## 验证与重新构建

```powershell
node tests/test_pages.cjs
python build_pages.py
```

测试检查在线演示版的数据初始化、刷新持久化、出入库、库存不足、预警、外键限制与恢复数据。重新构建会从标准测试数据生成 `docs/demo.sqlite` 并更新在线版页面，不改写 Python 本地版的运行数据库。
